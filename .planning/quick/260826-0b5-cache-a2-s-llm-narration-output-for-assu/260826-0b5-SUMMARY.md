# Quick Task 260826-0b5: Cache A2's LLM narration output for assurance-cards Summary

**Content-addressed in-process LRU memo cache around A2's `narrate_gap()` LLM call, cutting repeated-read Gemini traffic from one request per read to one request per distinct finding across all three call sites (`run_a2`, `get_assurance_cards`, `generate-capa`).**

## Performance

- **Duration:** ~55 min (includes three full-backend-suite pytest runs: ~18 min baseline, ~5 min targeted rerun, ~12.5 min final full-suite verification)
- **Tasks:** 3
- **Files modified:** 8 (2 created, 6 modified)

## Accomplishments

- `backend/app/narration_cache.py`: a standard-library-only (`hashlib` + `collections.OrderedDict`), bounded (256-entry, LRU-evicting) content-addressed memo cache. Imports nothing from `app.*` — structurally incapable of holding a compliance verdict, enforced by a grep gate in Task 1's verification.
- Wired into `narrate_gap()` in `backend/app/agents/a2_compliance.py`: the key is a digest of the exact, byte-identical prompt string sent to the LLM router, so every field reaching the model (`check_name`, `record_id`, `rule_id`, the whole `record!r`) is inside the key by construction. An edited record is a guaranteed miss. Degraded (fallback) router responses are never stored.
- Fixed the module-global test-state contamination this introduced: an autouse `conftest.py` fixture clears the cache before/after every test, plus one explicit mid-test clear in `test_a2_compliance.py`'s mocked-vs-degraded test (the one case the autouse fixture cannot reach, since both narration paths run inside a single test body).
- 12 new tests in `backend/tests/test_narration_cache.py` (UNIT / NEGATIVE / EDGE / INTEGRATION sections) prove: two-read memoization through the real `get_assurance_cards()` route function, per-field mutation invalidation (record.id, record.status, rule_id independently), a live Postgres UPDATE round-trip flowing through to fresh narration, a full cache hit still recomputing `confidence`/`db_record_found`/`opa_corroborated` live against an unreachable OPA, and outage-never-latches behavior.
- Documented the design rationale in `backend/README.md` (new section, after the existing Phase 4 sections; the 9-entry "Bible deviations" section is untouched) and extended `findings.py`'s module docstring (docstring-only diff, no code change).
- Discovered and logged (not fixed, per declared scope) that `app/llm_router.py`'s `load_dotenv()` picks up a truthy `GEMINI_API_KEY` from the repo-root `.env`, so any narration-exercising test without explicit key-stripping makes a real Gemini call during an ordinary `pytest` run — verified with a boolean-only check, no secret printed, recorded in `deferred-items.md`.

## Decisions Made

See `key-decisions` in frontmatter. The most consequential: caching happens inside `narrate_gap()` itself rather than in any one route, since `narrate_gap` has three call sites and `routes/actions.py::_find_finding_server_side` (the `generate-capa` path) was the worst offender — it narrates every failing check per POST just to match one `finding_id`. Function-level caching fixes all three call sites in a single change; route-level caching would have fixed only one.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] OPA traffic under `respx.mock` needed an explicit pass-through/mock route**

- **Found during:** Task 1, first test run of `test_integration_two_consecutive_assurance_card_reads_issue_one_request_per_finding`
- **Issue:** `get_assurance_cards()` calls C1's `verify_finding()`, which calls the live OPA sidecar at `127.0.0.1:8181`. Under a bare `respx.mock` block (registered only for the Gemini endpoint), respx's default `assert_all_mocked=True` intercepted the OPA request and raised `AllMockedAssertionError` instead of letting it reach the real OPA sidecar.
- **Fix:** Added `respx.route(host="127.0.0.1", port=8181).pass_through()` to every test that exercises `get_assurance_cards()` under `respx.mock`, mirroring the established pattern already used in `test_hero_tracer.py`. For the OPA-unreachable verdict-freshness test, the closed port (`:9`) needed a `.mock(side_effect=httpx.ConnectError(...))` rather than a bare closed-port connection attempt, since respx intercepts that port too and a real TCP refusal never occurs inside the mock context — this reproduces the same exception class (`httpx.ConnectError`, a `httpx.RequestError` subclass) that `opa_client.py`'s existing `except (httpx.RequestError, httpx.HTTPStatusError)` clause already handles.
- **Files modified:** `backend/tests/test_narration_cache.py`
- **Verification:** All 12 tests in `test_narration_cache.py` pass; the OPA-unreachable test asserts `opa_corroborated is False` and `confidence == "INSUFFICIENT_EVIDENCE"` on every card, proving the simulated outage was routed correctly.
- **Committed in:** `3059361` (Task 1, for the two-read test) and `a246438` (Task 2, for the verdict-freshness test)
