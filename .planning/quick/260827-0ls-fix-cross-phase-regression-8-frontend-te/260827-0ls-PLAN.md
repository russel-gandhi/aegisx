<interface_context>

Already read and confirmed from `frontend/src/lib/api.ts` — do NOT re-derive these, and
do NOT modify `api.ts`:

**Wire format `streamAssuranceCards` parses.** Frames are separated by a blank line
(`"\n\n"`). Within a frame, the parser takes the first line starting with `"data: "` and
`JSON.parse`s the remainder of that line. Chunks are buffered, never parsed directly — a
frame may legally arrive split across reads. On reader completion, a non-empty trimmed
remainder is dispatched as one final frame; nothing else is flushed.

**Frame union** (exported types `AssuranceCardStreamFrame`):
- `{ event: 'card', card: AssuranceCardData }` -> `handlers.onCard(frame.card)`
- `{ event: 'done', system_id: string, count: number }` -> `handlers.onDone(system_id, count)`
- `{ event: 'error', detail: string }` -> `handlers.onError(frame.detail)` — the field is
  `detail`, confirmed at api.ts:171 and dispatched at api.ts:234.

**Signature:** `streamAssuranceCards(systemId, handlers, signal?): Promise<void>` where
`handlers` is `{ onCard, onDone, onError }`. It requests
`${API_BASE}/api/systems/${encodeURIComponent(systemId)}/assurance-cards/stream` with
`{ headers: identityHeaders(), signal }`.

**Failure paths:** a non-`ok` response throws `ApiError(status, detail, message)` where
`detail` comes from the JSON body's `detail` field, falling back to
`` `Request failed with status ${status}` `` when the body is not JSON. A `null`
`response.body` throws `ApiError(0, 'empty stream body', ...)`.

**How the page consumes it** (`FindingInvestigation.tsx`, effect at line 96): `onCard`
appends to a `cards` array; `onDone` sets state `'ready'`; `onError` sets state
`'error'`; a rejected promise sets state `'error'` unless it is a `DOMException` named
`AbortError`. The all-checks-pass message renders only when state is `'ready'` AND
`cards.length === 0` — so a stream that never emits a terminal frame leaves the page
stuck on "Loading assurance cards...". The evidence-graph fetch is a separate,
independent effect using ordinary `apiGet`; its failure is swallowed and must stay a
plain-JSON mock.

**Existing test conventions to follow:** `vi.stubGlobal('fetch', vi.fn(...))` with
`vi.unstubAllGlobals()` in `afterEach`; explicit named imports from `'vitest'` (the suite
does not rely on `globals: true` for types); fixture values prefixed `FIXTURE-` so no
assertion can pass on the wrong field.
