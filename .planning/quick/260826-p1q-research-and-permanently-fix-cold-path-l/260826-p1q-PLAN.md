<objective>
The first assurance-card read for a system costs 18-50s. Four independent multipliers
stack: `get_assurance_cards` walks `A2_CHECKS` strictly sequentially, so up to four
serial LLM round trips; each trip goes to `gemini_flash_fast` at ~2.8s and on any
failure cascades to a second full-timeout attempt; `call_llm`'s `timeout=10.0` means a
hung provider costs 10s per attempt (20s with the cascade); and the whole thing is one
blocking JSON payload, so the browser shows nothing at all until the slowest card lands.

The already-merged `narration_cache` fixes the *second* read. This plan fixes the first
one, permanently, by attacking all four multipliers at once rather than patching the
symptom again.

Purpose: make the hero demo loop feel instantaneous without moving a single byte of
compliance judgement off the deterministic path. Every change here is about how fast
*decoration* arrives around an already-decided fact.

Output: Groq-routed narration with a hard 3s wall-clock ceiling; an SSE sibling route
that streams each card the moment its own C1 grade exists; concurrent per-check
execution behind both routes; a startup pre-warm so the demo's first human request is a
cache hit; a one-call fix to `generate-capa`'s server-side finding lookup; and a
frontend that paints cards as they arrive.

## What this plan explicitly does NOT touch

`verify_finding()` stays synchronous per finding, uncached, and un-sped-up.
`calculate_confidence()`, the ALCOA+ scorer, and every `passed` boolean are untouched.
The concurrency work moves *when* `verify_finding` is called (onto a task) but never
*whether* or *how*: each per-check coroutine awaits its own `verify_finding` to
completion before its card is emitted. A card is never streamed with a placeholder
confidence to be patched in later — that would put unverified content on screen, which
is the exact thesis violation CLAUDE.md forbids. Task 2's Rule-6 equivalence test exists
to *prove* this rather than assert it in a docstring.

## Design decisions and why

**Design Note 1 — SSE via `StreamingResponse`, read with `fetch`, not `EventSource`,
not the WebSocket.**
`app/ws/copilot.py` is a session-agnostic broadcast bus: `broadcast_json` sends every
frame to every connected client regardless of `session_id`, and its docstring records
that as a deliberate single-operator boundary. Assurance cards are request- and
system-scoped; reusing that socket means either inventing per-session filtering and a
correlation-id scheme, or leaking `GXP-MFG-DEMO-01` cards into a client viewing
`BUS-IT-DEMO-02`. Both are bigger than this task (Rule 7). Browser `EventSource` cannot
set request headers at all, and `lib/api.ts` sends `identityHeaders()` on every GET —
today `get_assurance_cards` has no `Depends(require_identity)`, so `EventSource` would
*appear* to work and would become unfixable the moment C2 RBAC extends to this route.
`fetch` + `body.getReader()` keeps the header convention and `ApiError` handling intact.
No new dependency: `sse-starlette` is not needed, `starlette.responses.StreamingResponse`
with `media_type="text/event-stream"` is sufficient.

**Design Note 2 — the 3s budget is a total wall-clock ceiling, and that deliberately
narrows the cascade.**
`call_llm` reuses its `timeout` value for the OpenRouter cascade attempt, so a raw
`timeout=3.0` yields a ~6s worst case. The ceiling is therefore enforced by
`asyncio.wait_for(call_llm(...), 3.0)` in `narrate_gap`. Consequence, stated here so a
reviewer does not later "fix" it as a bug: on a Groq **timeout** the outer `wait_for`
fires first and narration goes straight to the deterministic sentence — the cascade gets
no second attempt, because a 3s budget is a 3s budget. On a Groq **fast failure**
(missing key, 429, 5xx — all of which return in milliseconds) `call_llm`'s cascade to
OpenRouter still fires normally inside the remaining budget. The cascade is preserved as
CONTEXT.md requires; it is only the pathological hang that is cut short, which is exactly
what it was cut short for.

**Design Note 3 — the blocking route keeps its card ORDER, and gains concurrency anyway.**
Eleven existing test sites call the blocking route. `asyncio.gather` returns results in
*input* order, so the blocking route can run all four checks concurrently and still emit
cards in `A2_CHECKS` order — byte-identical output to today, just faster. The streaming
route uses `asyncio.as_completed` instead, because there the whole point is completion
order. Both drive the same extracted `_card_for_check()` helper so the two paths cannot
drift apart.

**Design Note 4 — a reasoning model needs an output floor, not just a cap.**
`openai/gpt-oss-120b` is a reasoning model and reasoning tokens count against
`max_completion_tokens`. A tight cap plus low reasoning effort can return
`finish_reason: "length"` with null content — which would currently raise a Pydantic
`ValidationError` inside `_parse_openai_compatible_response` that `call_llm` does not
catch, surfacing as a 500. Hence a generous 512-token cap, a null-coercing parse, and an
empty-text guard in `narrate_gap` that falls back to the deterministic sentence and
declines to cache it. A blank claim must never reach a card.
</objective>
