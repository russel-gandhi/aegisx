# Quick Task 261116-ul4: Fix the 2026-11-16 audit bugs

Source: the 2026-11-16 audit of the whole tree (live provider probes plus
respx-mocked reproductions). Baseline before any change, against live
Postgres/Qdrant/OPA: backend 719 passed / 3 failed; frontend 240 passed / 1
failed, `tsc -b` exit 2.

Rule 3 contract for each task: inputs, outputs, acceptance. Rule 4/5/6: every
fix ships with a test that fails before it and passes after it; critical-path
files (hash chain, C2, C3 approval route) get negative and edge cases.

## Task 1 — LLM routing no longer collapses to deterministic-fallback

Files: `backend/app/circuit_breaker.py`, `backend/app/rate_limiter.py`,
`backend/app/llm_router.py`, `backend/app/agents/a0_orchestrator.py`,
`backend/app/agents/a2_compliance.py`, `backend/app/agents/a7_remediation.py`,
`backend/app/agents/minimal_specialists.py`, `backend/app/routes/findings.py`,
`backend/app/routes/systems.py`, `backend/app/routes/copilot_query.py`.

1. Circuit breaker: a HALF_OPEN probe that is cancelled, raises an unexpected
   exception, or ends in a result that does not feed the breaker (HTTP 400,
   missing key, malformed body) must release the probe slot. A probe left
   in flight longer than a stale threshold is treated as abandoned.
   Accept: after a cancelled probe the next call is allowed to probe again.
2. Rate limiter: a live "remaining tokens" reading expires at the provider's
   own reported reset time, and refills linearly toward `tpm_limit` before it.
   Accept: a call after the reset window is sent, not rejected pre-flight.
3. Routing: hosted-first. Tasks are split across the three Groq chat models
   this account really serves (each has its own 8,000 tokens/min bucket,
   confirmed from live `x-ratelimit-*` headers): `openai/gpt-oss-120b`,
   `qwen/qwen3.8-27b`, `openai/gpt-oss-20b`. Ollama stays in the cascade as a
   local hop; OpenRouter stays last. The cascade skips by entry key, and skips
   a whole provider only on an account-level failure (missing key, 401/402/403).
   No inter-hop delay when the failed hop never sent a request.
4. A0: per-hop timeout fits inside the 2000ms budget so a cascade can happen.
5. `call_llm` never raises on a non-JSON 2xx body; an empty completion is a
   cascadable failure, not a successful blank answer.
6. A3-A6 narrations use `narration_cache` like A2 already does.
7. `GET /api/systems/{id}/readiness` counts open findings from the
   deterministic checks only; it no longer runs the narration fan-out.
8. Copilot evidence path rejects a blank synthesis answer.

## Task 2 — Deterministic-path and security defects

Files: `backend/app/audit_trail.py`, `backend/app/routes/actions.py`,
`backend/app/agents/c2_gateway.py`, `backend/app/routes/documents.py`,
`backend/app/routes/findings.py`, `backend/app/db.py`.

1. Approve/reject: the status transition is one conditional `UPDATE ... WHERE
   status = 'PENDING_APPROVAL'` in the same transaction as its audit event.
   Accept: two concurrent decisions on one proposal yield exactly one success,
   one 409, one audit row.
2. C2: extra deterministic jailbreak patterns alongside the Bible-literal one
   (recorded as a deviation); URL tokens are entropy-checked per segment so an
   ordinary URL is not flagged while an encoded blob inside one still is.
3. Upload: a `FAILED` document no longer blocks re-uploading the same bytes.
4. Assurance-card routes require identity and apply the C2 permission matrix.
5. `db.py` never logs the DSN password.
