# Quick Task 260827-045: Fix Critical Finding CR-01 (RBAC gate on audit tamper demo) Summary

**RBAC-gated `POST /api/audit/demonstrate-tamper` with `check_rbac(identity.role, "A7")` so only IT System Manager can invoke the audit-chain tamper demo, closing CR-01.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 1
- **Files modified:** 2

## Accomplishments
- Added a `check_rbac(identity.role, "A7")` guard as the first statement in `post_demonstrate_tamper`, before `acquire_pool_or_none` and before `log_event`, so a denied caller (Auditor or QA/Compliance) never reaches Postgres and no `TAMPER_DEMO_INVOKED` row is written.
- Documented, in a new route docstring, why "A7" is the correct capability id (its `PERMISSION_MATRIX` holder set is exactly IT System Manager, the intended allow set) and why it is unrelated to the `agent_id="C3"` recorded in the route's own `log_event` payload for audit attribution.
- Updated the module docstring to describe the route's identity handling as `require_identity` for attributability *plus* `check_rbac` for authorization, and to record that this closes CR-01.
- Added a parametrized denial test (`test_demonstrate_tamper_denies_non_it_manager_roles_before_any_write`) covering both Auditor and QA/Compliance: asserts 403 and that no `TAMPER_DEMO_INVOKED` row exists for that request's unique sentinel `event_id`, capturing any row found into `audit_chain_isolation` before asserting `None` so a regression is still cleaned up.
- The two pre-existing IT-System-Manager allow-path tests and the 422 no-headers test were left byte-for-byte unmodified and still pass.

## Files Created/Modified
- `backend/app/routes/audit.py` - Added `check_rbac` import, RBAC guard in `post_demonstrate_tamper`, route docstring explaining the A7/C3 id distinction, and updated module docstring
- `backend/tests/test_routes_audit.py` - Added `AUDITOR_HEADERS`/`QA_COMPLIANCE_HEADERS` constants and a parametrized 403-denial test proving no audit row is written on refusal

## Decisions Made
- Used `check_rbac(identity.role, "A7")` instead of a hardcoded `identity.role != "IT System Manager"` comparison (the review's illustrative snippet), per the plan's explicit design rationale: a role-name literal in the route would be a second, driftable copy of role authority outside `c2_gateway.PERMISSION_MATRIX`.
- Did not add a new `action_type` to audit-log denied attempts — logging denials would itself require a pool round trip ahead of the RBAC decision, defeating "deny before any write." Recorded as an accepted low-severity Repudiation risk in the plan's threat register (T-Q045-03).

## Deviations from Plan

None - plan executed exactly as written. The guard shape, docstring content, test structure (parametrized over both denied roles, capture-then-assert-None idiom, unique sentinel `event_id` per case), and header-constant naming all match the plan's `<action>` and `<read_first>` guidance directly.
