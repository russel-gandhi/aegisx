<objective>
Prove the entire Phase 4 evidence-graph architecture end to end on the thinnest
real path: one system, one requirement, one test case, one FK-derived edge —
read from live Postgres by NetworkX, persisted into the `graph_nodes`/`graph_edges`
cache tables, served as JSON by a read-only endpoint, and rendered in the browser
by React Flow.

**User story (MVP mode):** **As a** QA/Compliance user, **I want to** open the
Blast Radius page and see the real evidence relationships that exist in the
system's own database, **so that** I can see what is connected to what without
taking an AI's word for it.

Purpose: every architectural decision this phase rests on — cache-not-source-of-truth
(D-01), explicit-rebuild-only (D-02), type-prefixed node ids, allowlisted relation
types, the endpoint shapes, and the React Flow wiring — is proven against live
state in this one plan, before plans 04-02 through 04-05 expand horizontally on
top of it. If any of them is wrong, it is wrong after one commit, not ten.

Output: `networkx` installed and pinned; `backend/app/graph/evidence_graph.py`
with `build_graph`/`persist_graph`/`load_graph`; a `backend/app/routes/` package
with the rebuild and read endpoints registered on the FastAPI app; a `/blast-radius`
frontend route rendering the live graph; backend and frontend tests for all of it.
</objective>

|---|---|---|
| `NodeSpec` | `NamedTuple(table: str, property_columns: Tuple[str, ...], scope: Any)` | `scope` names how that node type's rows are selected for one system: the literal column name `"id"` (the system row itself), `"system_id"` (a directly system-scoped table), or the tuple `("via_parent", parent_node_type, fk_column)` for a table reachable only through a parent's primary key. | `NODE_SPECS` | `Dict[str, NodeSpec]` | Frozen allowlist: node type -> `NodeSpec`. This plan populates `SYSTEM`, `REQUIREMENT`, `TEST_CASE` only; 04-02 extends it. Table names reach SQL only from here. |

| Boundary | Description |

| Browser → FastAPI | `system_id` arrives as an untrusted path parameter and reaches SQL |
| FastAPI → Postgres | Graph construction and cache persistence build statements from allowlisted table names plus bound values |
| Postgres row → API response | Domain-table column values cross back out to an unauthenticated HTTP response |

| T-04-01 | Tampering | `system_id` path param in `routes/evidence_graph.py`, `build_graph`, `load_graph`, `persist_graph` | high | mitigate | Every `system_id` reaches SQL only through an asyncpg `$1` placeholder; no f-string ever interpolates it. Mirrors `c1_verifier.py`'s established convention. |

No table name is ever derived from a request or a row. |
| T-04-04 | Information Disclosure | `graph_nodes.properties` serialized into the GET response | medium | mitigate | `_add_node` copies only the columns named in that node type's `property_columns` tuple — no `SELECT *` spread — so an unlisted column cannot reach an unauthenticated response. |
