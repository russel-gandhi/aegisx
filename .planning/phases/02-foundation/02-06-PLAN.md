<objective>
Build the LangGraph orchestration skeleton: the `AgentState` schema, eleven stub nodes, and the fixed request topology `C2 -> A0 -> [A1...A6 in parallel via Send] -> C1 -> A7 -> C3`, compiling and executing end to end with stub returns.

This plan covers Build-Map ticket **SENT-1-06** (LangGraph `StateGraph` skeleton), which BRANCHING.md §4 marks Opus-design / Sonnet-implementation and §6 gates behind SENT-1-05 — hence wave 2 depending on plan 02-03.

The design work is already done and is not this plan's to redo. Bible Section 1.2 fixes the topology, and CLAUDE.md states it as a constraint: the topology is *fixed*. What this plan owes is a faithful implementation plus a test suite that asserts the shape structurally, because "the graph compiles" is a far weaker claim than "the graph has these eleven nodes and exactly these edges", and only the second one protects the topology from drifting as real agents replace stubs across the next three phases.

Purpose: every agent in Phase 3 is a node substitution inside this graph. If the edges are wrong now, C1 fans in on incomplete findings and the hero loop verifies against partial evidence — a failure that would look like working software.
Output: One graph module and a structural topology suite.
</objective>

Transcribe Bible Section 1.2 as the implementation, not as a reference to reinterpret. Every one of the eleven nodes is intentionally a stub in this phase, and the stub return values are themselves part of the specification because the tests assert on them.

Define three `TypedDict` classes: `AgentFinding` (finding_id, claim, regulatory_citations, confidence_score, evidence_ids, alcoa_score as `Dict[str, bool]`, model_attribution), `ActionProposal` (action_type, target_system, payload, justification), and `AgentState`.

`AgentState` carries eight keys, three of which are annotated with reducers and are the whole reason the parallel fan-out works:
- `messages: Annotated[list[BaseMessage], add_messages]`
- `system_id: str`, `user_intent: str`, `active_agents: List[str]`
- `findings: Annotated[List[AgentFinding], operator.add]`
- `proposed_actions: Annotated[List[ActionProposal], operator.add]`
- `verification_results: Dict[str, Any]`, `final_synthesis: str`

The two `operator.add` reducers are load-bearing. Six specialist branches return `{"findings": [...]}` concurrently, and without the reducer the last writer wins and five agents' findings vanish silently — which would present as C1 verifying a suspiciously small evidence set rather than as an error.

Define the eleven async node functions with the Bible's exact stub returns: `safety_gateway_c2` returns `{"user_intent": "safe"}`; `orchestrator_a0` returns `{"active_agents": ["A1", "A2", "A3", "A4", "A5", "A6"]}`; `system_knowledge_a1`, `compliance_a2`, `risk_a3`, `change_a4`, `incident_a5`, and `access_a6` each return `{"findings": []}`; `evidence_verifier_c1` returns `{"verification_results": {"verified": True}}`; `remediation_a7` returns `{"proposed_actions": []}`; `action_gateway_c3` returns `{"final_synthesis": "Execution complete. Actions queued for approval."}`.

Put no LLM client, no database connection, and no OPA call inside any node. Beyond being out of scope for this ticket (CLAUDE.md Rule 7), three of these nodes are deterministic decision points that Bible Section 1.3 permanently forbids an LLM from occupying: C2 makes the RBAC and injection-detection call, C1 makes the evidence-verification call, C3 makes the action-category routing call. Add a module-level comment recording that constraint so a later contributor filling in a stub reads it before, not after.

Define `route_specialists(state) -> List[Send]` returning one `Send(agent_name, {"messages": state["messages"], "system_id": state["system_id"]})` per entry in `state["active_agents"]`. Note that this is what makes ORC-02's Phase 3 subset routing a data change rather than a topology change: A0 narrows `active_agents` and the fan-out follows.

Build the graph in the Bible's order: add all eleven nodes under the exact string ids `C2`, `A0`, `A1`, `A2`, `A3`, `A4`, `A5`, `A6`, `C1`, `A7`, `C3`; set the entry point to `C2`; add the direct edge `C2 -> A0`; add the conditional edges from `A0` via `route_specialists` with the path list `["A1", "A2", "A3", "A4", "A5", "A6"]`; add a direct edge from each of the six specialists to `C1`; then `C1 -> A7`, `A7 -> C3`, and `C3 -> END`.

Expose both objects at module level: `graph` (the uncompiled `StateGraph` builder) and `compiled_graph = graph.compile()`. Exporting the builder as well as the compiled result is deliberate — the topology tests in Task 2 assert against the builder's node and edge collections, which is a far more direct and version-stable assertion than parsing a rendered diagram.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user request -> graph entry point | Every request enters at C2, which is the RBAC and injection-detection gate. In this phase C2 is a stub that admits everything. |
| specialist nodes -> C1 fan-in | Six concurrent branches merge into one state. The reducer decides whether all six contributions survive. |
| graph state -> API boundary | `TypedDict` state is unvalidated by construction; validation happens only where it is converted to a Pydantic model. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-24 | Elevation of Privilege | C2 stub admits every request | high | accept | Deliberate and scoped: SENT-1-06's contract is stub returns, and C2's real RBAC and injection logic is Phase 5 (SAFE-01, SAFE-02, SENT-4-01/4-02). The risk is bounded because no node downstream performs any write, executes any action, or reaches any external system in this phase. The mitigation that matters is structural and is delivered here: C2 is the entry point, so there is no code path that reaches A0 without passing through it. |
| T-02-25 | Tampering | a topology edit that silently drops a specialist | high | mitigate | An A-node quietly disconnected from C1 would make C1 fan in on five agents' findings and still return a confident verdict — working-looking software producing an under-evidenced conclusion. Mitigated by whole-collection equality assertions on both the node set and the edge set, plus an explicit assertion on A0's conditional destination list. |
| T-02-26 | Tampering | a lost reducer silently discarding findings | high | mitigate | Without `operator.add`, five of six parallel branches' findings are overwritten with no error. | T-02-28 | Denial of Service | an unbounded or hanging node | low | accept | Every node is a literal-returning coroutine with no I/O, so it cannot hang. Timeout behaviour becomes real in Phase 3 with ORC-02's 2000ms A0 fallback, which is tested explicitly there. |
