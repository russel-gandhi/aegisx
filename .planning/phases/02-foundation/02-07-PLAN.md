<objective>
Establish the WebSocket connection pattern end to end: a FastAPI route at the Bible's specified path that accepts a connection and echoes frames, and a browser client on the Copilot page that connects and renders what it receives.

This plan covers Build-Map ticket **SENT-1-08** (WebSocket connection pattern). Per BRANCHING.md §4 it owns "the backend WebSocket route module and the frontend WebSocket client module". It sits in wave 2 because a route needs an application to attach to (plan 02-03) and a client needs a page to live on (plan 02-04).

The contract is deliberately small: accept a connection and echo a test event. It is explicitly *not* streaming real agent state — LangGraph `astream_events` streaming needs real agents, which arrive in Phase 3, and the live agent topology it drives is Phase 6 (UI-04). What this plan proves is that the transport works across the process boundary in this environment, on these ports, in this browser. That is the thing most likely to be quietly broken, and the thing every later streaming feature assumes.

Purpose: Phase 5's human approval queue pushes pending `ActionProposal` records over this connection (REM-04, UI-02), and Phase 6 streams agent state transitions over it. Both are additions to a working pipe, or debugging sessions against a broken one.
Output: A backend route module, a frontend client module, a wired page, and tests on both sides.
</objective>

In `copilot.py`, declare a `fastapi.APIRouter` and register an async WebSocket handler on the path `/api/copilot/stream/{session_id}`, taking `websocket: WebSocket` and `session_id: str`. Use a router rather than decorating `app` directly, so this module stays importable and testable on its own and `main.py` gains exactly one line.

Send JSON on every frame, never bare text, including the `connected` frame. Every later use of this connection — proposal pushes in Phase 5, agent state transitions in Phase 6 — is structured, and a client written against a mixed text-and-JSON stream needs rewriting the first time that changes. Give the module a docstring recording the two frame shapes as the wire contract.

Create `frontend/src/lib/ws.ts` exporting a typed client.

Define the two frame types matching the backend's wire contract exactly — a `connected` frame carrying `session_id`, and an `echo` frame carrying `payload` — as a discriminated union on the `event` field. A union rather than a loose record matters because Phase 5 adds a proposal-push frame and Phase 6 adds agent-state frames to this same stream; a discriminated union makes each addition a compile-time prompt to handle the new case, while a loose record makes it a runtime surprise.

Export `connectCopilotStream(sessionId, handlers)` returning a handle with a `close()` function. Resolve the base URL from `import.meta.env.VITE_COPILOT_WS_BASE` with a default of `ws://127.0.0.1:8000`. The default is correct for local development, which is deliberate: it keeps this plan clear of `.env.example`, a cross-cutting file that BRANCHING.md §5 requires be changed in its own separate PR.

Wrap the JSON parse in a try/catch and route a failure to an `onError` handler. An exception thrown inside a socket's `onmessage` does not close the socket but does abort that handler invocation, so an unguarded parse turns one malformed frame into a connection that appears alive and silently stops delivering — the hardest class of bug to diagnose in this stack.

Rewrite `frontend/src/pages/Copilot.tsx` to connect on mount and clean up on unmount, keeping the existing `AgentTopologyCanvas` mount from plan 02-04 in place. On connect, send the literal text `test-event`, then render the connection status and a list of received frames. Rendering the frames is what makes the ticket's "backend to browser" claim observable by a human rather than inferred from a passing test.

Render only what the socket delivered and what this component authored. This tier's rule, stated in `frontend/README.md` since Phase 1, is that UI is built from server-trusted data and never from model-generated markup. Nothing here renders as HTML.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> backend WebSocket on 8000 | A long-lived, bidirectional channel that any local process can open. Unlike a REST call it is not preflighted by the browser's CORS model. |
| client-supplied `session_id` path parameter | Attacker-controlled input that in later phases will select which session's state is streamed. |
| client text frames -> server handler | Arbitrary client-supplied data crossing into server code on every frame. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-29 | Spoofing | unauthenticated `session_id` | medium | accept | Recorded as an accepted gap in 02-RESEARCH.md's Security Domain table and closed in Phase 5 when C2 exists (SAFE-01, SENT-4-01). Bounded for now because the handler holds no session state, reads no database, and returns only the caller's own frames — there is nothing to disclose across sessions because nothing is stored per session. A comment on the parameter names Phase 5 so the gap stays visible. |
| T-02-30 | Information Disclosure | echoing arbitrary client input | low | accept | The endpoint returns the sender their own payload and nothing else. It is a mirror, not a data source. This changes materially in Phase 5 when real proposals are pushed, which is why session validation is scheduled for the same phase. |
| T-02-31 | Denial of Service | unbounded connections or frame sizes | low | accept | Localhost-only, single-developer, demo-scale. Starlette applies its own frame-size limits. Connection limits and backpressure belong to the Phase 7 performance and reliability pass (SENT-6-07), not to a skeleton ticket. |
| T-02-32 | Tampering | LLM-generated markup rendered from a frame | medium | mitigate | The client parses JSON into typed objects and the page renders text, never HTML. The tier rule in `frontend/README.md` — server-trusted data only, never model-generated markup — is the standing control, and it matters most on exactly this channel, since Phase 6 streams model-adjacent agent state over it. |
| T-02-33 | Denial of Service | a malformed frame silently killing the listener | medium | mitigate | An unguarded `JSON.parse` inside `onmessage` aborts that handler while leaving the socket open, producing a connection that looks alive and delivers nothing. Mitigated by the try/catch and error path, with a test asserting the malformed case reaches `onError` rather than throwing. |
| T-02-34 | Elevation of Privilege | overly permissive CORS added speculatively | low | mitigate | No CORS middleware is added. WebSocket handshakes are not subject to the CORS preflight model, the frontend makes no `fetch` call to the backend in this phase, and the reasoning is recorded in the route module's docstring so it is not silently reversed later. |
| T-02-SC | Tampering | package-manager installs | high | mitigate | This plan installs no package on either side. FastAPI ships WebSocket support through Starlette, `uvicorn[standard]` already provides the `websockets` implementation, and the browser's native `WebSocket` needs no library. |
</threat_model>
