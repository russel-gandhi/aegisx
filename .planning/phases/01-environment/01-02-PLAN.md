    Sections:

    1. **Model** — trunk-based development (D-03). `main` is always green: it builds, its tests pass, and `bash infra/health-check.sh` exits 0 against it. Work happens on short-lived branches cut from `main` and merged back by PR. No long-lived integration branches.

    3. **Worktrees for parallel agents** — give the exact command `git worktree add ../sentinel-SENT-1-03 -b SENT-1-03 main`, and the cleanup pair `git worktree remove ../sentinel-SENT-1-03` after merge. State why: separate worktrees give each parallel agent its own checkout, so two agents cannot write the same file in the same working tree even by accident.

Any change to them is its own small PR, merged before the tickets that depend on it start. This is exactly how Phase 1 itself sequenced plan 01-01 and plan 01-03 against the same Compose file.

    6. **Merge rules** — a branch merges when its ticket contract is met, its tests pass (including the failure path, per Rules 4/5), and, for a `Critical`-review ticket, it carries unit, negative, edge-case, and integration coverage plus the stronger review pass (Rule 6).     7. **Conflict resolution** — resolve conflicts by hand on the feature branch, or, when two tickets genuinely need the same file, stop and raise a reviewed integration task rather than letting either agent guess. Do not resolve a conflict in a `Critical` path by taking one side wholesale.
