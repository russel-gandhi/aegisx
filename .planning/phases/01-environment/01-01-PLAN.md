    Write `infra/health-check.sh`, a pure assertion script. It observes and reports; it never starts, stops, or modifies anything. Waiting for readiness is Compose's job via `docker compose up -d --wait` (RESEARCH.md "Don't Hand-Roll"), so this script does not poll.

    Shape and behavior:
    - Shebang `#!/usr/bin/env bash`, then `set -uo pipefail`. Do not use `set -e`: the script must survey every service and report all of them, not abort at the first red one.
    - `cd` to the repo root, derived from the script's own location, so it works when invoked from any directory.
    - A `dc()` wrapper function that runs `docker compose "$@"` if `docker compose version` exits 0, otherwise falls back to `docker-compose "$@"`. ENV-01 and the Bible name the hyphenated form; Docker Desktop ships it as a shim over v2. Supporting both means the gate does not depend on which form the developer's machine provides.
    - Positional args are the service names to check. With no args, default to the array `postgres qdrant opa` — the exact set named in ENV-01.
    - For each service, assert two independent facts and print one aligned status line per service:
      1. Container health. Resolve the container with `cid=$(dc ps -q "$svc")`. Empty means NOT RUNNING (red). Otherwise read `docker inspect -f '{{if .State.Health}}{{.State.Health.Status}}{{else}}no-healthcheck{{end}}' "$cid"`. Only the literal `healthy` is green; `no-healthcheck` is red, because D-06 requires every service to declare one.
      2. Host port reachability, which is what ENV-01's "on ports 5432/6333/8181" actually claims and which container health alone does not prove. Use a case statement keyed on the service name: for `postgres`, `node -e "require('net').connect(5432,'127.0.0.1').on('connect',function(){process.exit(0)}).on('error',function(){process.exit(1)})"`; for `qdrant`, `node -e "fetch('http://127.0.0.1:6333/readyz').then(function(r){process.exit(r.ok?0:1)}).catch(function(){process.exit(1)})"`; for `opa`, `node -e "fetch('http://127.0.0.1:8181/health').then(function(r){process.exit(r.ok?0:1)}).catch(function(){process.exit(1)})"`. Use `node` rather than `curl` — `curl` is unreliable under Windows Git Bash (MSYS path and SSL mangling) and this is the developer's platform. An unknown service name is red with reason `unknown service`.
    - Do not swallow failures into a passing default. Never write a construct that substitutes a fallback value when a lookup fails and then compares it — that produces a gate which certifies while measuring nothing.
    - Print a final line `ALL HEALTHY` and exit 0 only when every requested service passed both assertions; otherwise print `NOT ALL HEALTHY` and exit 1.
    - Register the file as executable in git with `git update-index --add --chmod=+x infra/health-check.sh` so it stays runnable on Linux and in CI.

    Run it against the live Postgres from Task 1 and against a deliberately absent service to prove both branches.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git repository → every clone and the remote | Anything committed is replicated permanently and is visible to anyone with repo access |
| Host network → published container ports | Whatever reaches the published port talks to Postgres directly, with only the database password in front of it |
| Docker Hub registry → local image cache | Pulled image content executes on the developer workstation with container privileges |
| Host filesystem → container bind mount | `./infra/postgres/initdb` is mounted into the Postgres container's init path |
