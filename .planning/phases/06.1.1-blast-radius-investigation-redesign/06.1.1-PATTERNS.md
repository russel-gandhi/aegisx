# Phase 06.1.1: Pattern Map

## Deep-link / fetch-effect pattern (reuse, don't reinvent)
`frontend/src/pages/BlastRadius.tsx` lines 27-118 — `useSearchParams`-seeded initial state, cancelled-guard `useEffect` fetch, a ref-guarded "skip first run" effect for derived-state resets. `Copilot.tsx`/`Actions.tsx`/`FindingInvestigation.tsx` use the same shape project-wide (per CONTEXT.md). New `?system=` write support and any new `?origin=` param must follow this exact pattern — do not introduce a different state-management approach (no external router-state lib, no context provider) for this one page.

## Presentational-component purity pattern (reuse)
`EvidenceGraphCanvas.tsx`, `NodeDetailPanel.tsx`, `BlastRadiusPanel.tsx` are all pure: props in, JSX out, zero `fetch`, zero derived business logic beyond display formatting (`stringifyPropertyValue`, `allEmpty`). The redesign must preserve this — any new computation (path highlighting, impact severity classification for color) belongs in a plain exported function in a `lib/` module (testable without React), imported and called by the component, not inlined as component-internal derived state logic mixed with JSX.

## Route-map centralization pattern (reuse for D-09 verification, do not duplicate)
`frontend/src/lib/navigation.ts` is the sole place that turns a server-given `kind`+`target_id` into a path. Any Wave 3 Copilot-navigation work must call `navigationHref`/`evidenceHref` — never construct a `/blast-radius?...` string ad hoc elsewhere (would reintroduce the open-redirect surface D-13 closed).

## Visual language precedent (constrain new UI to this)
`AssuranceCard.tsx`'s CLAIM/EVIDENCE/RULE card structure — flat, bordered (`border-slate-800`), no shadows, no gradients, restrained accent use (matches `UI_SPEC.md`'s explicit "not vibe-coded" rules already enforced project-wide in `frontend/src/pages/Knowledge.tsx`, `EvidenceView.tsx`). New investigation-panel/relationship-card components must match this token set (`slate-800`/`slate-900`/`slate-100`/`slate-400` + one semantic accent per state), not introduce new colors, radii, or elevation.

## Testing pattern (reuse)
Existing tests for these components (if any — check `frontend/src/__tests__/`) use React Testing Library with mocked `fetch`/API modules, colour-class grep assertions (per 06.1's own VERIFICATION.md note that colour fidelity is grep-based, not screenshot-based), and pure-function unit tests for anything non-React (mirrors `navigation.test.ts`'s 24 named tests). The path-highlighting BFS function must ship as its own pure, directly-unit-tested module, matching this precedent — not tested only indirectly through component rendering.
