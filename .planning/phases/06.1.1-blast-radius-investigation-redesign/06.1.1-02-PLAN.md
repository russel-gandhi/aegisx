<action>
Create `frontend/src/lib/graphTraversal.ts` exporting:
- `buildAdjacency(edges: EvidenceGraphEdge[]): Map<string, string[]>` — builds an undirected adjacency map (both `source_id -> target_id` and `target_id -> source_id`, since "path back to origin" is direction-agnostic for a display highlight, not a dependency-direction claim) from the edge list, once per graph load.
- `shortestPathNodeIds(adjacency: Map<string, string[]>, fromNodeId: string, toNodeId: string): string[] | null` — plain BFS returning the ordered list of node ids on the shortest path (inclusive of both ends), or `null` if no path exists (disconnected nodes are a real, valid case — return `null`, do not throw).

In `BlastRadius.tsx`, track an `investigationOriginId` (the first node selected in a session, or explicitly re-anchored — reuse existing `selectedNodeId` as both current-selection and origin unless the file's Wave-1 header work introduced a distinct origin concept; if it did, wire path highlighting from origin to the newly selected node). On each node selection, call `buildAdjacency(data.edges)` (memoize with `useMemo` keyed on `data`) then `shortestPathNodeIds(...)`, and pass the resulting node-id array (or `null`) down to `EvidenceGraphCanvas` as a new `highlightedPath?: string[] | null` prop.

In `EvidenceGraphCanvas.tsx`, accept `highlightedPath` and use it in `toFlowNodes`: nodes in the path get full opacity, nodes not in the path (when `highlightedPath` is non-null and non-empty) get a dimmed style (e.g. `opacity: 0.35`) — reuse the `nodeVisualState`/`NODE_STATE_COLORS` module from 06.1.1-01, extending it with a `dimmed` boolean/state rather than duplicating color logic.
</action>

- `shortestPathNodeIds` returns `null` for two nodes with no connecting path in a test fixture graph, and the correct ordered path for a connected fixture (at least one 3+ hop test case)
- `EvidenceGraphCanvas.tsx` visually distinguishes at least two states (in-path vs dimmed) when `highlightedPath` is provided, verified by asserting on the computed `style`/opacity value per node in a unit test, not by pixel comparison
- `npx vitest run graphTraversal` exits 0
</acceptance_criteria>
</task>
