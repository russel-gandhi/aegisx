<critical_findings>
**Route the provider mock by request content, not by URL alone.** A0 and A2 both call the same Gemini `generateContent` endpoint with the same model, so a single respx route returning one fixed body would feed A0's classification JSON into A2's narration or vice versa. Install a side-effect callable that inspects the outgoing request body and returns the classification JSON when it carries A0's routing prompt, and a narration sentence otherwise. Mock the DeepSeek, Groq, and OpenRouter endpoints too, so the fully-keyed run exercises every specialist's primary provider rather than silently falling through cascades.

**`BUS-IT-DEMO-02` is the discrimination control.** It is the healthy seeded system: no periodic evaluation, no URS document, no requirements. Running the loop against it produces findings whose evidence records do not exist, which C1 grades INSUFFICIENT_EVIDENCE. Without this control the test cannot distinguish a working verifier from one that grades everything the same way.

**Do not weaken an assertion to make the run pass.** If the loop produces a grade this plan does not predict, the cause is upstream drift in a prior plan's contract, not a bad expectation here. Investigate and report it; adjusting the assertion would hide exactly the failure this gate exists to catch.
</critical_findings>
