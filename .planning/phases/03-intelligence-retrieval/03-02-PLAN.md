**Arithmetic this tracer depends on.** `ALCOAScore()`'s Bible-mandated non-uniform defaults give 6 true fields (attributable/contemporaneous/original are False; the other six are True). If the executor sees `HIGH` or `LOW` here, something upstream drifted — investigate, do not adjust the formula.

`AgentFinding` (the `TypedDict` in `graph/state.py`, unchanged shape, now with a pinned value convention):

| Field | Convention this phase |
|-------|-----------------------|
| `finding_id` | `"{AGENT}-{RULE_ID}-{RECORD_ID}"`, e.g. `A2-ANNEX11-S11-PE-001-PE-2024-01` |
| `claim` | Narrative sentence. LLM-narrated when the router succeeds; a deterministic template when it degrades. |
| `regulatory_citations` | The OPA rule ids from `policies/gxp_rules.rego` that ground this finding, e.g. `["ANNEX11-S11-PE-001"]`. These ids carry the Bible's own `# Source:` regulatory mapping and are the only permitted citation source (CLAUDE.md Rule 13 — never model recall). |
| `confidence_score` | `"UNVERIFIED"` on emission by any A-agent. Only C1 assigns `HIGH` / `MEDIUM` / `LOW` / `INSUFFICIENT_EVIDENCE`. The one exception is a Bible-specified failure-behavior finding, which carries `"LOW"` verbatim per Section 2. |
| `evidence_ids` | Postgres primary keys of the rows the claim rests on, e.g. `["PE-2024-01"]`. |
| `alcoa_score` | `ALCOAScore().model_dump()` — all 9 boolean fields present. |
| `model_attribution` | `LLMResponse.model_id` when the router succeeded; the literal `deterministic-fallback` when it degraded. |

`verification_results` (C1's output into `AgentState`) is a dict keyed by `finding_id`, each value being `{"confidence": str, "db_record_found": bool, "opa_corroborated": bool, "opa_rule_ids": List[str], "evidence_ids": List[str]}`.
</interface_contract>

**`backend/app/agents/a2_compliance.py`** — one deterministic check, one narration, one finding.

  - `async def verify_periodic_eval_current(pool, system_id: str) -> dict` — runs `SELECT id, due_date_ns, status FROM periodic_evaluations WHERE system_id = $1 ORDER BY due_date_ns DESC LIMIT 1` with a `$1` placeholder, compares `due_date_ns` against `time.time_ns()`, and returns `{"check": "verify_periodic_eval_current", "rule_id": "ANNEX11-S11-PE-001", "passed": bool, "record": dict | None}`. `passed` is True only when a row exists and its `due_date_ns` is not in the past. The pass/fail comparison is Python arithmetic — no model is consulted (Bible Section 1.3, D-03).
  - `A2_SYSTEM_PROMPT: str` — the Bible Section 6 "A2: Compliance Agent Prompt" text transcribed verbatim as a module constant.
  - `async def narrate_gap(check_result: dict) -> tuple[str, str]` — builds a user prompt from the already-computed check result and the real record, awaits the router with `task="compliance"` (which selects the thinking-off Gemini entry) and a 10-second timeout, and returns `(claim_text, model_id)`. On a degraded router response, returns a deterministic template sentence naming the rule id, the record id, and the overdue state, paired with the literal `deterministic-fallback`. The narration may only rephrase the boolean the check already produced; it can never change `passed`.
  - `def build_finding(check_result: dict, claim: str, model_id: str) -> dict` — assembles the `AgentFinding` exactly per this plan's `<interface_contract>` table.
  - `async def run_a2(state) -> dict` — obtains a pool via the wave-1 helper that returns `None` instead of raising; if the pool is `None`, returns the Bible's A2 failure behavior (a `LOW`-confidence finding whose claim cites that traceability verification failed, with empty `evidence_ids`); otherwise runs the one check and returns `{"findings": [finding]}` when it fails, or `{"findings": []}` when it passes. A passing check produces no gap and therefore no finding in the tracer.

Any DB-sourced text that reaches the narration prompt is untrusted data and is passed as content to be summarized, never as instructions to follow (the pattern the Bible's own A1 prompt establishes).

**`backend/app/agents/c1_verifier.py`** — deterministic Python only. This module must never contain a model call; that constraint is permanent, not a stub-stage convenience (Bible Section 1.3, `graph/state.py` module docstring).

  - `ALCOA_DIMENSION_COUNT = 9` with an inline comment recording D-06 and pointing at the `backend/README.md` deviation entry Task 2 writes.
  - `def calculate_confidence(finding: dict, db_record: dict, opa_evaluation: bool) -> str` — transcribed from Bible Section 2 with `ALCOA_DIMENSION_COUNT` substituted for the literal `8` and nothing else changed: start at 100; return `INSUFFICIENT_EVIDENCE` immediately when `db_record` is falsy; subtract `(ALCOA_DIMENSION_COUNT - sum(finding.get('alcoa_score', {}).values())) * 10`; subtract 100 more when `opa_evaluation` is falsy; then return `HIGH` above 80, `MEDIUM` at 50 or above, `LOW` above 0, and `INSUFFICIENT_EVIDENCE` otherwise.
  - `RULE_EVIDENCE_TABLES: dict[str, str]` — a frozen mapping from each of the ten rule ids in `policies/gxp_rules.rego` to the Postgres table its `record_id` lives in: documents, access_reviews, risks, incidents, requirements, suppliers, periodic_evaluations, gxp_systems, access_records, changes respectively. A table name can never be a bound parameter, so it comes from this allowlist and nowhere else; an unrecognised rule id returns no record rather than building a statement (ASVS V5).
  - `async def fetch_evidence_record(pool, finding: dict) -> dict | None` — resolves the finding's first citation through `RULE_EVIDENCE_TABLES` and its first `evidence_ids` entry through a `$1` placeholder, returning the row as a dict or `None`.   - `RULE_OPA_INPUT: dict[str, tuple]` — a second frozen mapping from each of the ten rule ids to the input keys its OPA payload needs, each entry a tuple of `(input_key, table_name, shape)` triples where `shape` is either a list or an object-keyed-by-id form. Populate all ten entries now: this is a constant table, not code, so filling it completely costs nothing and means no later plan ever has to edit this module to support a new rule. Rule 5 needs both `requirements` (list) and `test_cases` (object keyed by id — the one non-list input key in the whole bundle, per `gxp_rules.rego` lines 83-86); rule 10 needs both `changes` and `change_actions` (both lists); the other eight need a single list key each.
  - `async def build_opa_payload(pool, finding: dict) -> dict` — a single data-driven assembly over `RULE_OPA_INPUT`, reading real Postgres rows for the finding's rule and emitting the bundle keyed exactly as `policies/gxp_rules.rego` documents. No per-rule `if` branches: the shape difference between a list key and an object-keyed key is data in the table, not control flow here. The tracer exercises only the `periodic_evaluations` path; the other nine are reachable by data alone.
  - `async def verify_finding(pool, finding: dict) -> dict` — fetches the record; when it is `None`, returns the verification-result dict with `INSUFFICIENT_EVIDENCE` and skips the policy call entirely (no policy call is needed to know the evidence is absent). Otherwise calls the existing Phase-2 OPA client with the assembled payload — the real sidecar, never a mock, never a second Python copy of the rule logic — and sets `opa_corroborated` True when the returned violation set contains an entry whose `rule_id` is among the finding's citations and whose `record_id` is among its `evidence_ids`. Passes that boolean into `calculate_confidence()` and returns the `verification_results` value shape from the `<interface_contract>` table.
  - `async def run_c1(state) -> dict` — iterates `state["findings"]`, verifies each, and returns `{"verification_results": {finding_id: result}}`. With no findings, returns an empty mapping — never a hardcoded verified literal.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres row content -> LLM narration prompt | `risk_summary`, `description`, and similar free-text columns are untrusted data that reach a model prompt |
| finding content -> SQL statement construction | A finding's rule id selects a table name, which cannot be a bound parameter |
| OPA sidecar -> C1 scoring | Violation dicts are external data that drive a compliance decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Elevation of Privilege (indirect prompt injection) | `a2_compliance.narrate_gap` | medium | mitigate | DB-sourced text enters the prompt as content to summarize, never as instructions; the narration cannot alter `passed`, which is already computed before the call. C2's deterministic detector lands in Phase 5. |
| T-03-08 | Tampering (SQL injection via table name) | `c1_verifier.fetch_evidence_record` | high | mitigate | Table names come only from the frozen 10-entry `RULE_EVIDENCE_TABLES` allowlist; record ids bind through `$1`. An unrecognised rule id returns no record rather than building a statement. Gated by the `f"SELECT` grep check outputting `0`. |
| T-03-09 | Spoofing (unverified claim treated as verified) | `c1_verifier.run_c1` | critical | mitigate | `confidence_score` is `UNVERIFIED` on emission and only C1 assigns a real grade; C1 with no findings returns an empty mapping rather than a verified literal. This is the product's core thesis — the tracer asserts it on the live path. |
| T-03-10 | Repudiation | `model_attribution` | medium | mitigate | Every finding records the actual model id used, or `deterministic-fallback` when none was, per Bible Section 8.2's auditability requirement. Asserted on both tracer paths. |
| T-03-11 | Denial of Service | narration call inside a graph node | medium | mitigate | The narration call carries an explicit 10-second timeout and the router takes no retry beyond its single cascade, so a hung provider cannot block the graph indefinitely. |
