# Phase 06.1 Plan 06: Copilot Chat — Real Grounded Answers, Inspectable Evidence, Honest Trace Summary

**Any free-text Copilot question now routes to the real compiled StateGraph via `investigateCopilot()`, rendering a grounded answer with an expandable "How AegisX searched" six-stage trace and an inspectable evidence list — while the hero-query SSE fast path and C2's injection-block bubble stay byte-for-byte unchanged.**

- **Duration:** ~30 min
- **Completed:** 2026-08-29
- **Tasks:** 3/3 completed
- **Files modified:** 7 (4 created, 3 modified)

## Accomplishments

- `EvidenceView.tsx`: pure-presentation retrieval-evidence list reusing `AssuranceCard.tsx`'s `SectionLabel` convention and confidence colour classes verbatim; fixed per-item render order (SOURCE → SECTION/PAGE → RETRIEVAL METHOD → SCORES → why-selected); a `null` `section`/`page` renders as explicit "no section"/"n/a" rather than a silent gap; retrieval-method and evidence-type badges use only neutral `slate-800`/`slate-300` classes (no accent hue, so "hybrid" is never implied to be better than "semantic"); a 5-item visible cap with a "Show N more" expander that keeps all items in the DOM and keyboard-reachable when collapsed
- `InvestigationTrace.tsx`: six-stage retrieval trace, collapsed by default behind an "How AegisX searched" toggle, rendering complete (`✓`, `emerald-600`) vs. skipped (`-`, `slate-500`) glyphs purely from the response's own stage metadata — no `setTimeout`/`setInterval` anywhere, no state that advances a stage after mount, a 40ms-per-row fade-in stagger that runs once on mount
- `ChatMessage.tsx`: `ChatMessageData.kind` grows to `'text' | 'cards' | 'investigation'` (additive, the `'cards'` hero-query branch untouched); the new `investigation` branch renders, in the UI-SPEC's fixed order, the answer paragraph, a model-attribution subtext line, `InvestigationTrace`, then `EvidenceView` — or, when `insufficient_evidence` is true, only `EvidenceView`'s own insufficient-evidence copy (no answer, no trace)
- `Copilot.tsx`: any non-hero-query free text now calls `investigateCopilot(trimmed, selectedSystemId)` instead of the retired `UNRECOGNIZED_SHAPE_COPY` fallback; a new system `<select>` (reusing `BlastRadius.tsx`'s markup) defaults to `GXP-MFG-DEMO-01` and is sent with every investigate request; a `blocked: true` response still renders through the exact same destructive-styled bubble and `injectionDetectedCopy()` call as Phase 6; a rejected request renders `INVESTIGATE_FAILURE_COPY` (a literal alias of `STREAM_FAILURE_COPY`); `matchHeroQuery`/`KNOWN_SYSTEM_IDS`/`runHeroQuery`/`streamAssuranceCards` are all byte-for-byte unchanged
- 19 new named tests (11 `EvidenceView.test.tsx` + 8 `InvestigationTrace.test.tsx`) plus `Copilot.test.tsx` rewritten to mock `investigateCopilot` at the HTTP boundary (9 new free-text-investigation tests, all 7 pre-existing hero-query tests passing with unmodified bodies); full frontend suite green at 196/196, `tsc -b --noEmit` clean, `npm run lint` exit 0
