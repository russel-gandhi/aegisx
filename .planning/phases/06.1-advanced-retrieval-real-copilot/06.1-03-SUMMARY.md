# Phase 06.1 Plan 03: Advanced Ranking -- RRF, Batched Reranking, Parent-Context + Graph Evidence Summary

**`hybrid_retrieve()` now runs dense (Qdrant) and lexical (BM25) search concurrently, fuses both ranked lists with Reciprocal Rank Fusion, reranks the fused set in exactly one batched Gemini call whose scores are clamped and gate evidence sufficiency deterministically, and completes Section 15.7's provenance with batched parent-context lookups and zero-model-call graph-relationship evidence reused from the existing NetworkX evidence graph.**

## Accomplishments

- `app/retrieval/lexical.py`: `tokenize`/`build_corpus`/`bm25_search` using `rank_bm25.BM25Okapi` over `document_chunks`, hyphenated GxP identifiers (`URS-042`) kept as single tokens, corpus capped at `BM25_CORPUS_MAX_CHUNKS` (5000) and rebuilt fresh per query (deliberately uncached -- never serves stale results for a just-reingested document)
- `hybrid_search.py`: `reciprocal_rank_fusion()` (pure, `RRF_K=60`); `hybrid_retrieve()` reworked to run the dense and BM25 legs via `asyncio.gather(..., return_exceptions=True)`, emit `combining` as `complete` naming both candidate counts, and degrade to lexical-only evidence (not insufficient) when the embedding or Qdrant leg alone is unavailable
- `rerank_batch()`: one `call_llm(task="rerank", json_output=True)` call scoring every (truncated to `RERANK_MAX_CANDIDATES=40`) fused candidate jointly, with the untrusted-data framing copied from `_narration_prompt`'s wording; scores clamped to `[0.0, 1.0]`, non-numeric/unknown-`chunk_id` entries discarded; degrades to `({}, "deterministic-fallback")` on any failure, never raises
- `"rerank"` registered in `llm_router.PROVIDER_CONFIG["gemini_flash_fast"]["use_for"]` (backend/README.md Deviation 12 / code Deviation 17) -- routed through the existing provider table rather than a local `sentence-transformers` cross-encoder, per Bible Section 15.3's own configuration-follows-architecture allowance
- `hybrid_retrieve()`'s gate: `reranker_score >= RERANK_RELEVANCE_THRESHOLD` (0.35) when reranking succeeds, falling back to the Task 1 dense-score-or-BM25-presence gate when it degrades; `reranking` stage reported `complete`/`skipped` accordingly, never permanently `skipped`
- `expand_parent_context()`: one batched Postgres query resolves every surviving evidence item's `parent_section` and a `PARENT_CONTEXT_MAX_CHARS`-capped parent excerpt for the synthesis prompt, never touching the item's own quoted `content`
- `expand_graph_evidence()`: reuses `app.graph.evidence_graph`'s `make_node_id`/`load_graph`/`G.successors`/`G.predecessors` verbatim -- zero new graph logic, zero model calls -- for up to `GRAPH_EVIDENCE_LIMIT=5` one-hop relationships per query; a document whose graph node is not yet cached (Pitfall 2) degrades to no graph items for that document rather than raising
- 50 new/updated named tests across `test_hybrid_search.py` (27->47), `test_llm_router.py` (+1), and `test_routes_copilot_investigate.py` (updated 1 for real Task 3 behavior); full backend suite green at 522 passed, zero regressions after the one documented deviation fix below

## Issues Encountered

- `rank_bm25`'s own IDF formula (`log((N - n + 0.5) / (n + 0.5))`) is negative for a single-document corpus and exactly zero for a two-document corpus when a term appears in exactly one of them -- both pathological cases relative to this plan's small hand-built test fixtures. Resolved by ensuring every fusion-behavior test's BM25 corpus includes at least two distractor documents alongside the target content (confirmed live against the installed `rank-bm25==0.2.2` before writing the fixture helper).
- `reciprocal_rank_fusion`'s own docstring originally used the literal word "await" while documenting that the function contains no `await` -- tripped its own `"await" not in inspect.getsource(...)` test. Reworded the docstring to describe the same fact without the literal substring.
- The pre-existing `test_module_makes_no_chat_completion_call` test (06.1-02) asserted `not hasattr(hybrid_search, "call_llm")` -- a Task-2-superseded invariant now that `rerank_batch` genuinely needs `call_llm`. Renamed and rewrote the test to assert the more precise invariant this module now actually holds: `call_llm` is referenced, but never inside `reciprocal_rank_fusion`'s own pure-function body.
