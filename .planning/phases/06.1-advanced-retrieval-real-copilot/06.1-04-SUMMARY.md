# Phase 06.1 Plan 04: Binary Format Ingestion + Knowledge List + Auto Graph Rebuild Summary

**PDF/DOCX/CSV now ingest alongside Markdown, each carrying format-honest provenance (real PDF pages, DOCX headings, CSV row blocks); `detect_format` rejects any extension/content mismatch before a parser ever runs; `GET /api/documents` reports a real chunk count and read-time status; and a successful upload now auto-rebuilds the evidence graph so it's never invisible to Blast Radius.**

## Accomplishments

- `parse_pdf`: `pypdf`-based extraction with real 1-indexed page numbers and a length/period/case heading heuristic, in-memory only, capped at `MAX_PDF_PAGES=500`, degrading to `[]` (never raising) on any unparseable input
- `parse_docx`: `python-docx`-based extraction using real `Heading N` paragraph styles for `section`, folding table cell text into blocks under the last heading seen, `page` always `None`
- `parse_csv`: a dedicated structured row/column path (25-row blocks, header line repeated per block, `col: value` pairs) -- CSV never touches the prose chunker, per D-04
- `detect_format`/`parse_document`: an extension-AND-magic-bytes dispatcher (`%PDF-`, `PK\x03\x04`, strict UTF-8) gating all four formats before any parse; a mismatch is a 415 with nothing written
- `GET /api/documents`: one `COUNT(*)`-joined query returning every document's real chunk count and a read-time-derived `READY`/`FAILED` status, optional `system_id` filter, identity-gated like the upload route
- `_rebuild_evidence_graph_for`: a successful upload now calls the exact `build_graph`/`persist_graph` pair `POST .../evidence-graph/rebuild` calls, for the affected `system_id` only -- closes `06.1-RESEARCH.md` Pitfall 2 (a just-uploaded document was previously invisible to Blast Radius/graph-expanded Copilot evidence until a separate manual rebuild)
- `make_fixtures.py`: a from-scratch minimal-PDF-byte-stream builder (no `reportlab` dependency) plus a `python-docx` builder, both deterministically regenerable from synthetic GxP-flavoured text
- 43 new named tests (26 unit, 17 route-level) across `test_retrieval_ingest.py`/`test_routes_documents.py`; full backend suite green at 442 passed (426 pre-existing + 16 net-new after accounting for the pre-existing 10), no regressions; live smoke confirmed all four formats ingest READY against `GXP-MFG-DEMO-01` and PDF chunks carry real `page` values in Postgres

## Decisions Made

- **Minimal PDF fixture hand-built via a raw PDF 1.4 object-graph writer, no `reportlab`.** The plan's own `<action>` named `reportlab` as an option "if already available" -- it is not in `requirements.txt`, and this repo's package-install discipline treats adding one mid-task as a Rule 3 exclusion (checkpoint-worthy, not unilateral). `pypdf`'s `PdfWriter` offers no simple text-drawing API either, so `make_fixtures.py` writes the PDF object graph directly (catalog/pages/font/content-stream objects with `Tj`/`T*` text operators), verified to round-trip line-for-line through `pypdf.PageObject.extract_text()`.
- **FAILED/parsing envelope keys on `len(raw) > 0`, not merely `not blocks`.** The plan's Task 2 `<action>` item 4 describes this as "a non-empty payload of a non-CSV format" that parses to zero blocks -- distinguishing a genuinely-empty upload (not exercised by this plan's own tests, no regression risk) from a non-empty payload the parser could not make sense of (the actual honest-failure case).
- **`GET /api/documents`'s `failed_stage` is always `None`, never inferred.** A stored `chunk_count` of zero cannot distinguish a parsing failure from an indexing failure without re-parsing the original bytes (which the route does not have); guessing either value would be exactly the "never fabricate" violation this codebase's module docstrings repeatedly warn against.
