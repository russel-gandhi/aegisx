<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → browser → API | A user-chosen file crosses into the application |
| API response → React render | Backend-supplied document titles (derived from user-controlled filenames) are rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.1-26 | Tampering | XSS via a document title crafted from a malicious filename | high | mitigate | Titles render as JSX text children only; `dangerouslySetInnerHTML` is absent from the file and asserted absent by an acceptance grep; React escapes text children by construction |
| T-06.1-27 | Spoofing | client-invented ingestion status or chunk count | high | mitigate | Every rendered value reads from the `DocumentSummary` response; stage state is derived only from the upload response's `status`/`failed_stage`; timers are banned and the ban is grep-asserted, so no stage can advance without a backend fact |
| T-06.1-28 | Denial of Service | a very large local file selected by mistake | low | accept | The browser streams the body and the backend rejects at `MAX_UPLOAD_BYTES` with a 413 that renders `TOO_LARGE_COPY`; a client-side pre-check on `file.size` is a convenience, not the control |
| T-06.1-29 | Elevation of Privilege | upload issued without identity headers | medium | mitigate | `apiUpload` spreads `identityHeaders()` exactly as every other client call does; the backend's `require_identity` is the enforcing control |
| T-06.1-30 | Information Disclosure | listing documents across systems the role should not see | low | accept | The demo identity model has no per-system scoping today (all three demo roles see all systems, per `c2_gateway.PERMISSION_MATRIX`'s agent-level-only granularity); introducing per-system document scoping would be a new authorisation model and is out of scope for this phase — recorded here rather than silently assumed |
</threat_model>
