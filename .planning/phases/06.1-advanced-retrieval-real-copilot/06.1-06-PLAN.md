<objective>
Close the loop the whole phase exists for: a user types an ordinary question in the
Copilot chat and gets a grounded answer they can interrogate — the evidence behind it,
where each piece came from, how it was found, and an honest refusal when nothing
supports an answer (D-07, D-09, D-10, D-11, RAG-06, RAG-07).

Today `Copilot.tsx` gates every input through `matchHeroQuery()`; anything that is not
literally "audit ready" plus a known system id falls through to a canned "I can only
answer system-readiness questions right now" message. After this plan that gate is a
fast-path optimisation only — everything else reaches the real graph.

Purpose: retrieval that a user cannot inspect is indistinguishable from a chatbot.
`UI_SPEC.md` §11's evidence inspection is what makes this product's central claim —
"we never blindly trust AI" — visible rather than asserted.
Output: `EvidenceView.tsx`, `InvestigationTrace.tsx`, an extended `ChatMessage`, and a
`Copilot.tsx` that routes free text to `/api/copilot/investigate`.

Scope boundary with plan 06.1-08: this plan renders evidence as *text*. Turning each
citation into a link, and acting on the response's `navigation_target` (D-13), is plan
06.1-08's job and lands in the following wave, additively, against the components this
plan creates. Render no `<Link>`, no `<a href>` and no `useNavigate` call here — a
half-built navigation layer in two plans is harder to reconcile than a complete one in
the second. The `data-testid` attributes this plan puts on the evidence panel and on each
evidence item are the seams 06.1-08 attaches to, so keep them.
</objective>
