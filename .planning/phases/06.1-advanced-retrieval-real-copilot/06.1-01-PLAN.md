<objective>
Open the retrieval path end to end for the simplest real document format: a user
uploads a Markdown or plain-text GxP document against a known system and it becomes
genuine indexed evidence — parsed with its section headings preserved, chunked,
embedded through a hosted embedding API routed the same way every other model call
in this codebase is routed, and written to BOTH Postgres `document_chunks` (with the
D-02 structure columns) and a real Qdrant collection.

This is the phase's tracer slice (D-01 scope override, RAG-01/RAG-02). It also
freezes, in one place, every response contract the remaining six plans consume, so
no later plan has to guess a field name (RAG-05/RAG-06/RAG-07 shapes only —
population of the ranking fields lands in plans 02 and 03).

Purpose: Qdrant has been running healthy with zero collections and zero client code
since Phase 1. Until a document is really in it, nothing downstream in this phase
can be verified against real state rather than a fixture.
Output: `backend/app/retrieval/` package, the 004 migration, `POST /api/documents/upload`,
and the frozen Pydantic contracts in `app/schemas.py`.
</objective>
