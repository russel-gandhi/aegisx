<objective>
Close D-13: the Copilot's answer becomes navigable. Every citation is a link to the page
that holds it, and when the backend has determined that every citation points at one
single source, AegisX offers to take the user there — after the answer has rendered, with
a visible notice and a working way to decline.

Plan 06.1-02 already decided *whether* a destination is unambiguous, in Python, once,
server-side. This plan does not re-decide it. The browser's entire job here is to turn a
`kind` plus an entity id into a path from a fixed table, render a link, and — when the
server said the citations were unanimous — arm one cancellable timer.

Purpose: an answer whose evidence you cannot open is an answer you have to take on faith,
which is the exact posture this product exists to refuse. Deep links make every citation
checkable in one click; auto-navigation makes the unambiguous case feel like an
investigation rather than a lookup. The discipline that keeps this honest is that no
address ever crosses the API boundary: the response carries `kind` and `target_id`, never
a URL, so there is no channel through which an uploaded document's text — the most
attacker-influenced input in this phase — could become somewhere the browser goes.

Output: `lib/navigation.ts`, `AutoNavigateNotice.tsx`, deep links in `EvidenceView`, and
`?system=`/`?document=` param reads on the two landing pages.

Boundary with Phase 06.1.1: that phase's success criterion 5 (the Copilot resolving a
plain-language *request* — "show me the blast radius of CHANGE-2026-09" — into a
pre-focused Blast Radius view) is a different trigger for the same destination. It should
consume `lib/navigation.ts`'s route map rather than build a second one; this plan exists
partly so that phase has one to consume.
</objective>
