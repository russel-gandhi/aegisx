<objective>
Prove the Phase 5 architecture end to end on one path: a human with a role generates a CAPA proposal from an already-C1-verified finding, the proposal is deterministically categorised and parked PENDING_APPROVAL, and approving it is recorded in a hash-chained audit trail that `verify_chain()` can validate.

**User story (MVP mode, from the ROADMAP Phase 5 Goal):** **As a** QA/IT System Manager operating a GxP system, **I want to** have every proposed remediation write held for my explicit approval and every decision recorded in a tamper-evident log, **so that** no AI-proposed change can ever reach a validated record without a named human authorising it and leaving provable evidence.

This is the phase tracer: one entry point wired through every layer this phase touches (identity -> C2 RBAC -> A7 synthesis -> C3 category routing -> Postgres -> hash-chained audit trail -> HTTP response). It is production code, not a prototype — every module created here is the final module, and later plans expand coverage outward from it rather than replacing it.

Purpose: catch an architectural dead end (schema gap, canonicalisation mismatch, identity plumbing) after one commit instead of after six.
Output: the four new backend modules, the additive `action_proposals` migration, the two new HTTP routes, and an integration test that drives the whole path against live Postgres.
</objective>
